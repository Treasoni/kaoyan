# 手写笔记重构协议

## 目标与边界

目标是把用户手写中的思考路径重构成可学习、可核对、可复习的笔记，而不是只做 OCR 转写或改写成脱离原稿的通用讲义。

本协议由学科技能调用：数学保留其公式与推导规范，电子技术保留其电路图与方向检查。不要直接用于普通纯文本提问。

## 固定处理顺序

1. **视觉盘点**：文字、公式、箭头、框选、颜色、编号、图、曲线、表格、拓扑与留白。
2. **不确定项**：看不清的内容列为“待确认”，不得猜测。
3. **思路重建**：问题 → 核心结论 → 条件/符号 → 推导或判断链 → 做题启动条件。
4. **图文双轨**：图形知识重绘标准图，并写图的作用、关键标注、做题结论。
5. **原图溯源**：原图折叠保存，正文每个关键段可回指对应区域。

## 默认交付

1. 一句话结论；
2. 符号/标注速查；
3. 重构逻辑链；
4. 图示说明（适用时）；
5. 最小 SOP 或做题启动步骤；
6. 易错点与待确认项；
7. 手写来源与正文段落的对应关系。

用户明确要求“仅转写”时，可以省略扩展讲解，但不得省略不确定项标记和原图溯源。

## 安全与质量门槛

- 不修改、覆盖或删除用户原图。
- 不覆盖个人笔记、随手记、学习心得、踩坑记录、待探索或 `[!personal]` 块。
- 图形、曲线、拓扑、信号和流程关系必须保留标准图或重绘图、关键标注和做题结论；原图不能替代正文图。
- 看不清的手写文字、参数、方向或图意必须标为待确认，不能以通用知识补写。
- 写入前确认目标笔记；用户给出的路径优先。目标路径不明时，不创建文件。
- 写入后回读目标段，检查公式转义、表格、图片链接和来源对应关系。

## 学科交接

- 数学：重构前核验定义、条件、边界和推导链；推导内容遵循 `> [!note]-` 单一折叠块规范。
- 电子技术：重绘前核对器件、端口、接地、电源、输入输出、方向、反馈路径和悬空节点。
