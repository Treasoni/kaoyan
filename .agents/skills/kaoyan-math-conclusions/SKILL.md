# 考研数学做题结论整理

## 目标

把用户给出的证明、例题、分析或口诀，压缩成一条**可识别、可启动、可复习、可继续追加**的做题结论，并写入 Obsidian 聚合笔记。

默认目标文件为：

考研数学/0-基础知识/做题结论.md

这是“做题结论”技能，不是完整章节讲义：保留能帮助用户判断和启动解题的内容，长背景和完整教材内容留在来源笔记。

## 触发边界

### 使用本技能

- 用户说“把这个做题结论放入”“整理进做题结论”“加入做题结论”。
- 用户提供一道数学证明、例题、解题技巧或反例，并要求记录到做题结论笔记。
- 用户说“后续题目继续追加”，需要沿用已有排版。
- 当前笔记是做题结论聚合页，用户明确要求追加内容。

### 改用其他技能

- 只想听讲解、验证理解，不要求写入文件：使用数学学习或理解验证流程。
- 要整理完整章节：使用章节总结技能。
- 要记录错题及错误归因：使用错题本技能。
- 要生成独立知识点笔记，而不是聚合做题结论：使用考研数学笔记技能。

## 默认目标与读取纪律

1. 若用户提供了目标路径，以该路径作为唯一写入目标；不要另建同名笔记。
2. 若没有提供路径，优先使用当前笔记上下文；没有当前笔记时使用默认目标文件。
3. 写入前读取目标文件，确认现有标题树、分类、编号、结尾位置和个人内容保护区。
4. 同时读取用户本轮提供的原题、证明或截图文字。用户材料是本条结论的首要来源；必要时再查对应教材或章节资料。
5. 数学定义、定理、等式、边界条件和证明链先独立验算，再写入。发现原材料有笔误时，直接修正，并在最终回复中简短说明。
6. 目标文件不存在时，仅在用户明确要求“放入/追加”时创建最小聚合骨架；不要因为普通讲题请求自动建文件。

## 执行流程

### 1. 定位知识模块

先判断这条内容属于数列极限、函数极限、连续与间断、导数、中值定理、积分、级数或线性代数等模块。

- 已有对应的二级标题：追加到该模块。
- 没有对应模块：在“后续新增结论”占位标题之前建立新的模块标题。
- 没有占位标题：在文件末尾追加模块，但保留已有内容和结尾结构。
- 不按题目表面形式乱分类，按真正调用的知识点归类。

### 2. 检查重复与编号

- 先检索已有标题、结论公式和关键词，避免同一结论重复建立条目。
- 若本质相同，补充到原条目；只有知识条件或解法本质不同才新建条目。
- 用户给出例题编号时保留该编号；未给编号时，沿用所在模块现有编号并生成下一个不冲突的编号。
- 不改动旧条目的题干、结论、个人笔记或错误记录。

### 3. 组织条目

每条优先按以下顺序整理，按内容需要裁剪，但不能只剩一句公式：

1. 题目/结论
2. 核心结论
3. 识别特征
4. 核心思想
5. 做题模板
6. 证明或推导
7. 典型应用、反例或特殊情形
8. 易错点
9. 一句话记忆

方法型结论必须同时写出：

- 为什么选择这个方法；
- 从题面到结论的分步操作；
- 至少一个关键中间状态、放缩关系或等价链。

证明和推导统一放在一个默认折叠的说明块中：

> [!note]- 证明

说明块前留空行，块内的独立公式使用单独的 $$ 行，不嵌套其他证明 callout。

### 4. Obsidian 数学格式

- 行内数学统一使用 $...$，块数学使用独立的 $$...$$。
- 绝对值使用 \lvert...\rvert；范数使用 \left\lVert...\right\rVert。
- 不使用 \(...\) 作为行内数学。
- 表格前后留空行；表格内避免复杂长公式。若必须写绝对值，不使用裸管道符，以免破坏表格。
- 证明、推导和长公式放折叠块，结论和做题启动语放在正文显眼位置。

### 5. 安全写入

- 使用相对路径进行 vault 操作；不要把 vault 绝对路径写入目标笔记。
- 增量插入，不整体重写聚合笔记。
- 不删除或覆盖以下区块：个人笔记、随手记、学习心得、踩坑记录、待探索，以及任何个人 callout。
- 按标题边界确定插入位置，不把裸分隔线当作唯一边界。
- 写入包含反斜杠、美元符号或 Markdown 特殊字符的内容时，使用外部脚本、Python 原始字符串、占位符或等价安全方法，避免命令层转义污染。
- 生成内部链接前先确认目标文件存在；无必要时不新增链接。

### 6. 写后验收

写入后必须：

1. 回读新增条目，确认题目、结论、公式、编号和分类正确；
2. 扫描控制字符，只允许换行、回车和制表符；
3. 检查行内数学分隔符成对，块数学标记成对；
4. 检查没有出现 \boxed、\text、\begin、\rvert 等被命令层截断或变成控制字符的情况；
5. 回看标题树，确认插入位置正确、旧内容未被移动或删除；
6. 如目标在 Git 中受跟踪，运行针对目标文件的差异检查，不执行破坏性 Git 操作。

## 输出

完成后用简短结果汇报：

- 写入的目标笔记；
- 新增或补充的模块/条目标题；
- 本次采用的核心做题结论；
- 数学与 Markdown 验收是否通过；
- 若修正了原材料中的笔误，说明修正点。
