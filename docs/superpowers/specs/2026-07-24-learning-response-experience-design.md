# 学习回答体验统一改造设计

## 目标

让考研项目的日常回答先匹配用户当下的学习目标，再调用对应学科知识、笔记流程和文件写入流程。第一轮同时解决：回答过长或不对题、跨技能路由不稳定、手写笔记整理失真、生成结果没有可回归验收标准。

## 方案选择

采用“统一回答层 + 现有学科能力”的轻量改造。

- 不采用 ExamPass 的完整批量生成与 HTML 流水线：它适合课件转学习包，日常答疑会过重。
- 不为每次回复强制多 Agent 审查：只在计算、推导、题目解析、手写重构等高风险场景启用双重校验。
- 保留既有数学、英语、专业课、计划、错题和 Obsidian 技能；统一层只决定意图、深度、输出结构和验收。

## 1. 统一回答模式

所有科目入口在确定学科后，先选择一种回答模式。除非用户明确指定，按请求动词和内容自动选择，不要求用户学习命令。

| 模式 | 适用请求 | 默认输出 |
| --- | --- | --- |
| 快速答疑 | “这一步为什么”“这是什么”“怎么判断” | 结论、关键 2-4 步、一个易错点、一个自检问句 |
| 概念学习 | “讲懂/整理这个知识点” | 钩子、TL;DR、为什么、是什么、怎么用、微型自测 |
| 题目讲解 | “这题怎么做/我哪里错了” | 题型定位、SOP、分步解、错因、下次触发点 |
| 笔记重构 | “整理笔记/图片/手写内容” | 来源盘点、重构正文、图示、速查、原图溯源 |
| 计划与复盘 | “今天怎么学/完成了什么” | 当日策略、时间块、兜底方案、汇报入口 |

任何模式都先解决当前问题；只有用户要求写入或需要长期保留时，才扩展为完整笔记和进度更新。

## 2. 路由规则

路由顺序固定为：

```text
请求动作/回答模式 → 学科 → 子模块 → 是否写入文件 → 质量门槛
```

这样“解释一道数学题”和“整理数学笔记”不会因为同属数学而得到同样冗长的输出。发生歧义时，先按低成本的快速答疑作答；只有目标文件、学科体系或答案正确性依赖缺失信息时，询问一个最小澄清问题。

## 3. 手写笔记重构

手写笔记、课堂板书、截图或照片不按普通文本处理。数学由 `kaoyan-math-notes`、电路类专业课由 `kaoyan-electronics-circuit` 调用共享协议：

1. 视觉盘点文字、公式、箭头、框选、颜色、图、电路、曲线和表格；
2. 将模糊区域显式标为待确认，不以常识补写；
3. 重建“问题 → 结论 → 条件/符号 → 推导或判断链 → 做题启动条件”；
4. 对图形知识提供标准重绘图及“图的作用、关键标注、做题结论”；
5. 原图作为可折叠来源保留，并与正文段落对应。

完整细则见 [手写笔记重构设计](2026-07-24-handwritten-note-reconstruction-design.md)。

## 4. 高风险质量门槛

| 场景 | 必做检查 |
| --- | --- |
| 数学计算/推导 | 独立验算；检查定义、条件、边界和推导链 |
| 专业课电路 | 检查拓扑、端口、接地、电源、方向和反馈路径 |
| 题目解析 | 先完整识别题目；答案、步骤和题干相互核对 |
| 手写笔记 | 图文双轨、待确认项、原图溯源、正文可独立学习 |
| 写入 Obsidian | 保护个人区块；回读公式、表格、图片链接与格式 |

普通解释不额外套审查清单，避免让回答变慢、变长。

## 5. 回归验收

建立一份不含个人隐私的回答样例集。每条样例包含“用户提问、期望模式、必须包含、不得出现”。第一轮至少覆盖：

1. 一句话数学答疑；
2. 数学综合题讲解；
3. 专业课电路图讲解；
4. 手写数学笔记；
5. 手写电路笔记；
6. 每日学习计划。

改动技能后，逐例检查路由、篇幅、核心结构和质量门槛是否符合预期；真实的“不满意回复”可持续加入样例集。

## 6. 实施边界与顺序

第一阶段修改共同规则与数学/专业课入口，使回答模式先于学科子模块选择。第二阶段接入手写笔记协议和图示检查。第三阶段增加样例集和检查清单，并同步 `.agents/skills` 与 `.claude/skills`。

第一轮不改变英语、计划、错题本的内部流程；它们只接入统一回答模式的最小规则，后续再按真实反馈专项优化。

## 验收标准

- 用户只问一小步时，不再获得整章笔记式输出；
- 用户给出手写笔记时，输出保留原有思路和图示，不把不清楚内容编造成事实；
- 数学、专业课的高风险回答都有对应的校验；
- 修改后 Codex 与 Claude 两套同名技能保持等价能力；
- 至少六个样例能够说明输出模式和质量检查实际生效。

## 实施状态

- 已实现：统一回答模式、入口路由、手写笔记重构协议、匿名回归样例和双平台一致性检查。
- 未自动化：对真实 LLM 回复的语义评分；该部分由回归样例的人工验收承担，后续用真实不满意回复持续扩充。
