# 手写笔记重构设计

## 目标

把用户提供的手写笔记、截图或照片转化为可学习、可核对、可复习的笔记；不把它简单转写成排版整齐但失去原有思路的通用讲义。

该能力服务于数学与 822 电子技术基础。它由两个科目入口路由到同一套处理规则，保留各学科已有的公式、电路图和错题规范。

## 非目标

- 不修改用户的原图或删除原始笔记。
- 不在看不清文字、参数、箭头或元件时自行猜测。
- 不为普通的纯文本提问启动完整重构流程。
- 不把 ExamPass 的 HTML 页面、批量提取脚本或多 Agent 编排整体搬入本项目。

## 路由

当用户提供手写笔记、手写照片、课堂板书截图，或要求“整理/重构/看懂这页笔记”时：

1. 数学请求由 `kaoyan-math` 路由到 `kaoyan-math-notes`；
2. 电路图、模电、数电请求由 `kaoyan-electronics` 路由到 `kaoyan-electronics-circuit`；
3. 两个子模块都必须读取共享的“手写笔记重构协议”。

若学科无法判断，先按协议进行视觉盘点；只有学科决定公式体系、图示含义或目标文件位置时，才询问一个最小澄清问题。

## 处理协议

### 1. 视觉盘点

先识别页面中的文字、公式、箭头、框选/颜色、编号、图形、电路连接、曲线、表格和留白。把看不清或无法判断的区域列为“待确认”，而非补写成一般知识。

### 2. 思路重建

按“这页要解决的问题 → 核心结论 → 条件/符号 → 推导或判断链 → 做题启动条件”重新组织。保留用户手写中有价值的口诀、顺序和易错提醒；教材补充只能作为补充，不能覆盖用户原有主线。

### 3. 图文双轨

只要原图包含曲线、几何位置、信号/波形、流程、边界关系或电路拓扑，主笔记必须提供清晰的标准图或重绘图，并附：图的作用、关键标注、做题结论。原图作为可折叠的溯源材料保留，不能代替正文图。

### 4. 可复习输出

默认输出包含：

1. 一句话核心结论；
2. 符号/标注速查；
3. 重构后的逻辑链；
4. 图示说明（如适用）；
5. 做题启动步骤或最小 SOP；
6. 易错点与待确认项；
7. 手写来源与正文段落的对应关系。

用户要求“仅转写”时，允许省略扩展讲解，但仍必须保留不确定项和原图溯源。

## 写入安全

- 写入前确认目标笔记；用户给出的路径优先。
- 不覆盖个人笔记、随手记、学习心得、踩坑记录、待探索或 `[!personal]` 块。
- 数学推导使用单一 `> [!note]-` 折叠块；数学公式和表格遵循项目的 LaTeX/Obsidian 规范。
- 电路重绘要检查端口、接地、电源、元件方向、反馈路径与悬空节点。

## 质量门槛

交付前逐项检查：

1. 每个核心公式、箭头/流程关系和关键图都有正文解释或“待确认”标记；
2. 没有把模糊识别结果伪装成确定事实；
3. 主笔记能独立学习，原图能回溯核对；
4. 图形知识没有被降级为纯文字；
5. 数学内容已校验定义、条件、边界与推导；电路内容已校验拓扑和方向；
6. 写入后回读目标段，检查公式转义、表格与图片链接。

## 验收样例

实现后应使用至少四类输入进行人工回归检查：

- 含公式推导和框选结论的数学笔记；
- 含函数曲线或几何箭头的数学笔记；
- 含电路图和电流/电压方向的专业课笔记；
- 含模糊文字或被遮挡参数的笔记。

每类样例均检查：重构逻辑、图示、待确认标记、原图溯源和既有笔记保护。

## 实施边界

第一轮只增加共享协议，并修改数学与电子技术入口的路由和质量检查；不引入新的默认日常入口，也不改变英语、计划、错题本等现有流程。

## 实施状态

- 已实现：统一回答模式、入口路由、手写笔记重构协议、匿名回归样例和双平台一致性检查。
- 未自动化：对真实 LLM 回复的语义评分；该部分由回归样例的人工验收承担，后续用真实不满意回复持续扩充。
